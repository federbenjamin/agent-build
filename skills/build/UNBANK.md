# /build — Unbank — a banked run resumes

`§` names below are CLOSE.md's headings.

When the operator has answered every question a run banked (CLOSE 4a, CLOSE step 12), that run resumes in its own run dir and ledger. It fixes only the banked rows, reads only that fix, and ships. No new run, no wave, no fix rounds.

1. **Enter the run tree.** When no tree holds the run's branch (step 12 removed it), add one first: `git worktree add <main checkout>/.claude/worktrees/run-<branch-slug> <branch>` with the sandbox off, then `EnterWorktree` with that `path`, then the `<install>` step, and the notes' stack setup when the unit touches the database. Note the head (`git rev-parse HEAD`, its own call): the run banked here. Flip each answered `question:` Todo line (CLOSE 4a) to `[x]`; in the question bank `<run-root>/<worktree>-<branch>/afk-questions.md`, when it exists, end each answered row's `## Q<n> — <id>` heading with ` (answered <date>: <the answer>)`, so SHIP step 1 no longer copies it as open.
2. **Fix the banked rows, and only them,** as the operator's answer says. Make the fix yourself, or spawn one fresh `fixer` on the owed model (CLOSE step 4) with `isolation: "worktree"`, and `git merge <b>` when it reports. Its dispatch names round `unbank`, the head, the brief path, each banked id with its question and the operator's answer, the run tree, and the run dir. Ledger: `unbank: <ids> | from=<the head step 1 noted> | sha=<head after the fix>`, with `| model=<m> | agent=<id>` when a fixer made it. A run has one `unbank:` line.
3. **One read of the fix.** `node ~/.agent-build/runtime/stagePlan.ts --run-dir <run-dir> --stage unbank` prints the range and the `hand-test:` line. Make the read's review tree, `<inputs-dir>/review-unbank-1` at the range end (CLOSE §Trees), and spawn ONE `review-cursory`: no Codex, and no other reader. Its dispatch names the range, the read root, the brief path, the operator's answers, stage `wave`, id prefix `CURSORY`, and its output `<run-dir>/unbank/review-cursory.md`; it checks its file with `--stage wave`. Ledger: `unbank-read: review-cursory | sha=<range end>`. You may read that one file. Fix its findings yourself, or by one more fresh fixer as in step 2; no read follows unless the operator asks for one.
4. **Hand test.** A fresh hand tester runs the claims the `hand-test:` line names (only claims whose last run failed), plus any you judge the fix reaches. None named and none chosen → none run. Each run writes its `hand-test-<n>:` line; then re-run `node ~/.agent-build/runtime/reviewTable.ts build --run-dir <run-dir> --round final`, since the final table reads that file.
5. **SHIP**, as for any run. The gate reads each `unbank:` id as answered: its `banked:` id, its table row, and its `final` open row no longer fail.
