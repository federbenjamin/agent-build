# /build — Drift at SHIP

Read this file in full when SHIP step 1 finds main drift. `§` names below are CLOSE.md's headings; step numbers outside this list are CLOSE's.

When the gate, or SHIP step 1, finds that `origin/main` changed this branch's files after the wave, the fix is a small drift group, never the whole wave again. A build has at most one drift group:

1. Note the pre-merge head (`git rev-parse HEAD`, its own call), then merge `origin/main` (conflict → resolve per hunk).
2. `node ~/.agent-build/runtime/stagePlan.ts --run-dir <run-dir> --stage drift --from <pre-merge head>` prints `stage drift-<g>` (`<g>` is the group's number, `1`: every name below uses it), the merge-side range (main's side, limited to the files main changed under the branch), and the reader.
3. `node ~/.agent-build/runtime/reviewTable.ts dispatch --run-dir <run-dir> --stage drift-<g> --reader review-cursory --out <inputs-dir>/dispatch-drift-<g>-review-cursory.txt`, then make the read's review tree, `<inputs-dir>/review-drift-<g>-1` at the merged head (CLOSE §Trees), and spawn ONE Claude `review-cursory` (no Codex, no other reader), read root that tree, over the merge-side patch stagePlan printed, with the full range as context; output `<run-dir>/stage-drift-<g>/review-cursory.md` (its `## Status` is `- none`; new ids `500`–`599`); it checks its file with `--stage drift-<g> --run-dir <run-dir>`. Ledger: `drift-read: review-cursory | from=<pre-merge head> | files=<n> | sha=<head it read>`.
4. `node ~/.agent-build/runtime/reviewTable.ts build --run-dir <run-dir> --round drift-<g>`; rows > 0 → a fresh `fixer` on the owed model, round `drift-<g>` (`table-drift-<g>.md`, `fix-drift-<g>.txt`); ledger `drift-fix: <fixed>/<rows> | model=<m> | agent=<id> | from=<sha> | sha=<sha>`.
5. When the drift fix changed a file: `node ~/.agent-build/runtime/stagePlan.ts --run-dir <run-dir> --stage drift-confirm` (it prints `stage drift-confirm-<g>`), then run the owed readers as CLOSE step 5, at stage `drift-confirm-<g>` (`node ~/.agent-build/runtime/reviewTable.ts dispatch --run-dir <run-dir> --stage drift-confirm-<g> --reader review-cursory-codex --out <inputs-dir>/dispatch-drift-confirm-<g>-review-cursory-codex.txt` first): one Codex read into `stage-drift-confirm-<g>/` (CLOSE §Codex fails at a read applies, with `--stage drift-confirm-<g>`), the verifier too when stagePlan owes it (an `amend brief:` in the range), and a fresh hand tester on the failed claims it names. Ledger `drift-confirm: review-cursory-codex[, build-verifier] | sha=<range end>`; `hand-test-<n>:`.
6. `node ~/.agent-build/runtime/reviewTable.ts build --run-dir <run-dir> --round final` again (CLOSE step 12; it carries the drift group's round), then CLOSE step 13: add to the ticket only the lines its first run did not add, and write a new `leftovers:` line with the new count and the same `scope=` (the last `leftovers:` line counts); then re-run the gate.

The gate judges the one group: its round, its `drift-fix:` line when the round had rows, and its `drift-confirm:` when that fix changed a file.

**Main moving again after the drift group is only merged.** No second group, no reader, no fixer, and no `<checks>` run of its own: `git fetch origin`, merge `origin/main` (conflict → resolve per hunk), then write `drift-merge: | from=<head before the merge> | sha=<head after the merge>`. Write one such line each time main moves again on the branch's files; SHIP's pre-push `<checks>` run and CI carry what changed.
